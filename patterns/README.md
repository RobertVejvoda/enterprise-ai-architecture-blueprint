# Architecture Patterns

This directory contains reusable patterns for recurring concerns in enterprise systems that use AI.

## Purpose

A pattern explains a recurring architecture problem, the context in which it occurs, the forces that shape the design, and a reusable vendor-neutral solution with explicit consequences.

## Initial Pattern Candidates

- document recognition;
- generative assistant;
- AI-assisted software development;
- decision support;
- human in the loop;
- external AI provider.

Pattern files will be created incrementally rather than as empty placeholders.

## Pattern Structure

Each pattern should normally cover:

- problem and context;
- forces and constraints;
- proposed solution;
- responsibilities and information flows;
- ArchiMate view or view guidance;
- security and control considerations;
- alternatives and consequences;
- applicability limits.

## Boundaries

Patterns reuse building blocks from [`../reference-architecture/`](../reference-architecture/) and refer to controls in [`../controls/`](../controls/). They should not duplicate regulatory text from [`../compliance/`](../compliance/).
