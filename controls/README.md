# Controls

This directory defines reusable architecture, security, operational, and governance controls for enterprise AI capabilities.

## Purpose

Controls translate risks, principles, and obligations into explicit expectations that can be implemented, reviewed, and evidenced.

## Planned Areas

- control catalogue;
- model governance;
- prompt governance;
- vendor governance;
- security controls;
- auditability.

## Control Structure

Each control should identify:

- control objective;
- risk or concern addressed;
- applicable architecture layer or lifecycle stage;
- required or recommended implementation behaviour;
- expected evidence;
- ownership and review expectations;
- relevant patterns, principles, or external obligations.

## Boundaries

Controls should remain technology-neutral. Regulatory interpretation belongs in [`../compliance/`](../compliance/), while concrete reusable solution structures belong in [`../patterns/`](../patterns/).
