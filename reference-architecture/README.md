# Reference Architecture

This directory describes the reusable logical architecture for enterprise systems that use AI capabilities.

## Purpose

The reference architecture provides stable building blocks, responsibilities, boundaries, information concepts, security concerns, and integration relationships without prescribing a specific vendor, platform, or implementation stack.

## Planned Areas

- logical architecture;
- information architecture;
- security architecture;
- integration architecture.

## Content Rules

- Describe responsibilities and interfaces before technology choices.
- Separate architecture building blocks from solution building blocks.
- Make ownership, trust boundaries, and human accountability explicit.
- Link to relevant ArchiMate views, controls, and patterns.
- State assumptions and known trade-offs.

## Boundaries

Reusable scenario-specific solutions belong in [`../patterns/`](../patterns/). Control definitions belong in [`../controls/`](../controls/). TOGAF method and roadmap artefacts belong in [`../togaf/`](../togaf/).
