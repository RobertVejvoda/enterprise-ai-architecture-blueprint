# TOGAF

This directory contains the method and architecture deliverables used to develop and govern the blueprint.

## Purpose

TOGAF is applied pragmatically to connect stakeholder concerns, architecture vision, capabilities, target state, transition planning, and implementation governance. The objective is traceability and decision quality, not process ceremony.

## Expected Content

Planned artefacts include:

- architecture principles;
- stakeholder map and concerns;
- architecture vision;
- capability assessment;
- baseline and target architecture summaries;
- transition roadmap;
- governance model.

## Boundaries

- Detailed ArchiMate views belong in [`../archimate/`](../archimate/).
- Reusable solution structures belong in [`../patterns/`](../patterns/).
- Technical architecture descriptions belong in [`../reference-architecture/`](../reference-architecture/).
- External regulatory mappings belong in [`../compliance/`](../compliance/).

## Contribution Guidance

Each artefact should state the concern it addresses, its scope, key assumptions, and links to related architecture views or decisions. Keep the method proportional to the architecture problem.
